## 2. Duplicated progress-PUT fetch in InterviewPrepModal (debounce save vs unmount flush)
- **Severity**: Medium
- **Category**: duplication
- **File**: `app/features/sub_schedule/InterviewPrepModal.tsx:78-86` (debounced save) and `:104-111` (unmount keepalive flush)
- **Evidence**: Two effects issue the identical request: `fetch(`/api/interview-prep?entry=${encodeURIComponent(entry.id)}`, { method: "PUT", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ checked, notes, interviewer }) }).catch(() => {})`. Grep `method: "PUT"` in `app/features/sub_schedule` → exactly these two hits (both this file). The bodies differ only in: debounced version reads the live `checked/notes/interviewer` closures; the unmount version reads `latestProgressRef.current` and adds `keepalive: true`. The URL, method, headers, body shape, and best-effort `.catch` are copy-pasted.
- **Impact**: The endpoint/body contract is duplicated; a field added to the PUT payload (e.g. a new prep-progress key) must be changed in both, and the two can desync. Low bug risk today but real edit-coupling cost.
- **Fix sketch**: Add one local helper `const putProgress = (p: { checked; notes; interviewer }, keepalive = false) => fetch(url, { method: "PUT", headers, body: JSON.stringify(p), keepalive }).catch(() => {})` and call it from both effects (`putProgress({ checked, notes, interviewer })` in the timeout; `putProgress(latestProgressRef.current, true)` on unmount). Keeps both effects' distinct lifecycles/guards (`dirtyRef`, the debounce timer, the keepalive flush) intact.
