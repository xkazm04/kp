## 1. CLI stdio-encoding boilerplate ignores the existing `configure_stdio()` helper
- **Severity**: Medium
- **Category**: duplication
- **File**: `pipeline/jobfit/cli.py:21-23`, `pipeline/jobfit/extract_cli.py:12-14`, `pipeline/jobfit/market_salary_cli.py:78-80` (consolidation target already exists: `pipeline/jobfit/_cli.py:21-26` `configure_stdio()`)
- **Evidence**: `_cli.configure_stdio()` was created precisely to centralize the `if hasattr(sys.stdout, "reconfigure"): sys.stdout.reconfigure(encoding="utf-8"); sys.stderr.reconfigure(...)` block (its module docstring states this), but only `match_cli`/`reasoning_cli`/`matrix_cli` call it (`grep configure_stdio` → 3 callers + the def). Meanwhile `grep "reconfigure(encoding"` returns ~17 hand-rolled copies across the package, three of which are in this context's scope (cli.py, extract_cli.py, market_salary_cli.py). The three in-scope copies are byte-identical to the helper except market_salary_cli adds `errors="replace"`.
- **Impact**: The exact bug the helper was meant to prevent — a Windows cp1250 console mangling Czech diacritics on a CLI that forgot the reconfigure — can silently reappear on any of these spawned bridges, and a future change to the encoding policy must be made in N places. The drift already exists (`errors="replace"` present in some, absent in others).
- **Fix sketch**: Replace the inline block in `cli.py` and `extract_cli.py` with `from ._cli import configure_stdio` + `configure_stdio()`. For `market_salary_cli.py`, either accept dropping `errors="replace"` (behaviour-preserving for valid UTF-8) or add an optional `errors: str = "strict"` param to `configure_stdio()` and pass `errors="replace"`. No caller-signature change; pure internal substitution. (The same substitution applies to the ~14 out-of-scope copies but those belong to other contexts.)

## 2. Letter-spacing regex near-duplicated across extractor and pipeline
- **Severity**: Medium
- **Category**: duplication
- **File**: `pipeline/jobfit/extractors.py:124-141` (`_LETTER_SPACED_RUN` + `collapse_letter_spacing`) and `pipeline/jobfit/pipeline.py:351-352` (`_letter_spacing_hits`)
- **Evidence**: `grep "letter_spac|collapse_letter|_LETTER_SPACED"` shows two independent regexes for the same phenomenon (pypdf emitting `K n o w l e d g e`). extractors: `(?<![^\W\d_])(?:[^\W\d_]\s){2,}[^\W\d_](?![^\W\d_])`; pipeline: `\b(?:[^\W\d_]\s){3,}[^\W\d_]\b`. Both encode the identical "run of single letters separated by single spaces" pattern with the same `[^\W\d_]` Unicode-letter class; they differ only in the run threshold (`{2,}` vs `{3,}`) and boundary style (lookarounds vs `\b`). The extractor REPAIRS the run; the pipeline COUNTS runs for the `ExtractionQuality` comparison — two consumers of one concept, defined twice.
- **Impact**: A correctness tweak to the letter-spacing pattern (e.g. accepting NBSP, or a new boundary case) must be mirrored in two regexes that already disagree on their threshold, so they can drift further; the `gemini_letter_spacing_hits` quality metric and the repair can silently diverge in what they consider "letter-spaced".
- **Fix sketch**: Move a single base pattern into `extractors.py` (e.g. expose `LETTER_SPACED_RUN` and a `count_letter_spacing(text) -> int`), have `pipeline._letter_spacing_hits` import and call it instead of re-compiling its own. Keep the `{2,}`-repair vs `{3,}`-count threshold difference explicit and documented (they are intentionally different sensitivities) rather than merged — the safe win is one shared regex source, not unified behaviour. Update the one caller (`compare_extraction_quality`, pipeline.py:332-333).

If yes, delete `extract_profile_text_with_gemini` and migrate the test to the deterministic extractor; if the Gemini-extraction quality check is intentionally retained, keep the function but mark it as a test-support utility (it should not be presented as a production extractor).
