## 1. Near-duplicate inline save-on-blur input components (`SpendInput` / `TargetInput`)
- **Severity**: Medium
- **Category**: duplication
- **File**: `app/features/sub_analytics/AnalyticsTab.tsx:677-747` (`SpendInput`) and `:858-937` (`TargetInput`)
- **Evidence**: The two function components are structurally near-identical. Both: (a) hold `draft`/`saving`/`failed` state; (b) use the exact in-render prop-resync idiom — `const [seeded, setSeeded] = useState(value); if (value !== seeded) { setSeeded(value); setDraft(...); }` (confirmed identical at lines 694-698 and 877-881 via grep `if \(value !== seeded\)` — only those two sites in this file); (c) validate `trimmed === "" ? null : Number(...)`, reject `!Number.isFinite || < 0`, and short-circuit `if (amount === value) return`; (d) `onBlur={save}` + `onKeyDown` Enter→blur; (e) render the same `focus-ring h-8 … rounded-md border px-2 text-right … ${failed ? "border-coral text-coral" : "border-stone-200 text-ink"}` input. They diverge only in: the POST endpoint + body shape (`/api/analytics/spend` `{channel, amountCzk}` vs `/api/analytics/targets` `{metric, value}`), an extra `MAX_AMOUNT_CZK`-style ceiling in spend (actually enforced server-side, not client), input width (`w-24` vs `w-20`), and the label wrapper (SpendInput is bare, TargetInput wraps a `<label>` row). Both components live only here (grep `SpendInput|TargetInput` across the repo → all references inside `AnalyticsTab.tsx`; 1 use of Spend, 3 of Target).
- **Impact**: ~70 duplicated lines; the subtle resync-on-prop-change pattern and the validation guard are copy-pasted, so a fix to one (e.g. tightening the numeric guard, or a focus/disabled bug) silently misses the other. Two payload shapes also means two places to keep in sync with the routes.
- **Fix sketch**: Extract one `InlineNumberSave` that takes `value: number | null`, `suffix`, `ariaLabel`/`label`, optional `width`, and an `onSave(value: number | null) => Promise<void>` callback (each caller owns its own `fetch`). Keep the resync/validation/blur logic in the shared component; `SpendInput` and `TargetInput` collapse to thin wrappers supplying their endpoint and label chrome. Pure client component — no node-test or import-freeness concern.

## 2. `kinds.<kind>` i18n-label resolution duplicated three ways across the two analytics views
- **Severity**: Low
- **Category**: duplication
- **File**: `app/features/sub_analytics/DecisionLog.tsx:124` and `:206`, plus `app/features/sub_analytics/AnalyticsTab.tsx:436`
- **Evidence**: The "decision-kind → human label" resolution is written three times with slightly different fallbacks: `DecisionLog.tsx:124` `k in DECISION_META ? t(\`kinds.${k}\`) : k.replace(/_/g, " ")`; `:206` `m.known ? t(\`kinds.${d.kind}\`) : d.kind.replace(/_/g, " ")`; `AnalyticsTab.tsx:436` `tLog(\`kinds.${kind}\`)` (no fallback — RoiLedger borrows the `analytics.log` namespace via `useTranslations("analytics.log")`). All three resolve against the same `DECISION_META` keyspace and `analytics.log.kinds.*` catalog (verified via grep `kinds\.\$\{` / `kindLabel`).
- **Impact**: Low — three small one-liners, but the fallback divergence is a latent inconsistency: a kind missing from the catalog renders the raw enum two of three places and may throw/empty in RoiLedger. A new event kind requires remembering all three.
- **Fix sketch**: A tiny shared `kindLabel(t, kind)` helper (e.g. in `decision-attribution.ts`, which both files already import, or a local `sub_analytics` util) that does the `kind in DECISION_META ? t(\`kinds.${kind}\`) : kind.replace(/_/g, " ")` resolution once. Cross-namespace caveat: RoiLedger uses the `analytics.log` translator instance — pass the resolved `t` in, don't hardcode the namespace. No import-freeness concern (client components).
