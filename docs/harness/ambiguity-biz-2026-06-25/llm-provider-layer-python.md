## 1. Benchmark harness is a built-but-unsurfaced cost-arbitrage engine
- **Lens**: 🚀 Business
- **Severity**: High
- **Category**: dark capability / monetization lever
- **File**: pipeline/jobfit/llm/bench/bench_cli.py:10
- **Observation**: `bench/` runs every production use case across `provider:model` columns over seeded data and produces exactly the numbers a buyer needs to pick a model — per-target `validRate`, `llmRate`, `p50/p95Ms`, mean tokens and `totalCostUsd` (runner.py:178-193). But it is a hand-run dev CLI that "spends REAL provider tokens — run deliberately… never from CI." The admin Models tab (`app/features/sub_models/KeysPanel.tsx`) only offers a single-canary **Test** button; nothing surfaces the cost/quality comparison that would let an operator or BYOM customer choose the *cheapest viable* model per use case.
- **Why it matters**: The entire reason to build a 4-provider abstraction is cost-arbitrage + BYOM differentiation. The measurement engine exists and is the hard part; leaving it as a manual CLI means the headline value ("we'll run your hiring AI on the cheapest model that still passes the contract") is never sold or shown. This is kp's known "built-but-unwired" pattern, applied to its strongest pricing lever.
- **Recommendation**: Persist `summary.json` rows into a small table and add a "Model comparison" card to the Models tab (use-case × target → valid%/llm%/p95/cost), with a one-click "set as default for this use case" that writes `llm_config`. Gate live runs behind an explicit admin action; show last-run results otherwise.
- **Effort**: M

## 2. No cross-provider failover — a provider outage silently degrades hiring output to template text
- **Lens**: 🌀 Ambiguity
- **Severity**: High
- **Category**: undocumented trade-off / resilience
- **File**: pipeline/jobfit/llm/base.py:254
- **Observation**: `complete()` retries the *same* provider up to 3×, then raises `LLMError`; the registry binds exactly one provider per use case (registry.py:47-76). Every call site catches that and drops to its **deterministic template** (capabilities.py:5-7: "the caller's deterministic fallback takes over… for runtime failures"). So when Anthropic returns 529s for 20 minutes, there is no "try Gemini instead" — every match rationale, screen, and outreach for that window is generated by the non-LLM fallback. This is a deliberate design choice (one engine, degrade to deterministic) but it is nowhere recorded as a decision, and its blast radius (silent quality cliff across live hiring decisions during any single-provider incident) is undocumented.
- **Why it matters**: "Provider-agnostic resilience" is an implied promise of a multi-provider layer; what's delivered is multi-provider *configuration* with single-provider *availability*. Reviewers and operators can't see that an outage means template-quality decisions rather than a second model. For a recruiting product, that's a silent correctness/credibility risk.
- **Recommendation**: Either (a) document explicitly in `docs/LLM_PROVIDER_LAYER.md` + the registry that there is intentionally no LLM-to-LLM failover and why, or (b) add an optional ordered fallback chain in `llm_config` (e.g. `anthropic → gemini`) that `complete()`/registry honors before the deterministic floor. Record the chosen trade-off either way.
- **Effort**: M

## 3. Capability matrix claims `file_input` for text-only adapters — the registry's own anti-misroute guarantee has a hole
- **Lens**: 🌀 Ambiguity
- **Severity**: High
- **Category**: false invariant / latent silent-wrong-output
- **File**: pipeline/jobfit/llm/capabilities.py:17
- **Observation**: `PROVIDER_CAPABILITIES` grants `CAP_FILE_INPUT` to `anthropic`, `openai`, and `azure_openai`, and `USE_CASE_REQUIREMENTS` makes `cv_analysis`/`profile_extract` require `file_input`. The module docstring (capabilities.py:4-7) advertises this as the protection that stops a wildcard config from "silently routing `cv_analysis` to a text-only provider." But **none of those adapters implement file input** — every `_call(self, prompt: str, …)` sends a plain text message only (anthropic_api.py:31, openai_api.py:25, gemini_api.py:32; gemini_api.py:2-7 even says the multimodal path "stays in gemini.py until Phase 3"). So a `"*": {provider:"anthropic"}` wildcard, or any future `resolve_provider("cv_analysis")` call site, passes capability validation and returns an adapter that drops the CV file. The guard works for `claude_cli` (no file_input tag) but not for the three adapters whose tag is aspirational.
- **Why it matters**: cv_analysis is the front door of the whole pipeline. The stated safety invariant is false for exactly the providers most likely to be configured, so the failure mode is a silent, contract-passing CV analysis run with no CV — a silent wrong hiring outcome the registry is documented to prevent.
- **Recommendation**: Until the adapters actually accept files, drop `CAP_FILE_INPUT` from the anthropic/openai/azure rows (leave it only where implemented) so the registry raises on a multimodal misroute as documented; or add a `_call` file-input path and a test asserting capability tags match adapter behavior.
- **Effort**: S

## 4. Durable usage ledger bills on hardcoded, self-admittedly-estimated non-Anthropic prices
- **Lens**: 🚀 Business
- **Severity**: Medium
- **Category**: billing accuracy / revenue risk
- **File**: pipeline/jobfit/llm/base.py:56
- **Observation**: `MTOK_PRICES` is a hand-maintained source-code table whose non-Anthropic rows are flagged "LOCAL ESTIMATES… verify against each provider's price book before billing on them." `price_usd()` stamps that figure onto every `LLMResult`, and `monitor._append_ledger` (monitor.py:73-91) writes it into the **durable** `llm_usage` ledger that is "deliberately INDEPENDENT of LightTrack — it must persist even when observability is off (the default deployment)." The "LightTrack is source of truth, ours is a cross-check" framing (base.py:48-51) only holds when LightTrack is configured, which it is not by default (monitor.py:56). So in the standard deployment the only spend record carries estimated, drift-prone prices for OpenAI/Gemini, with no mechanism that forces the estimate to be reconciled.
- **Why it matters**: For a product with a billing surface, reporting or charging usage on guessed token prices (or `cost_usd=None` whenever a freshly-pinned model doesn't prefix-match) understates/overstates real spend and erodes trust the first time a customer reconciles their provider invoice.
- **Recommendation**: Move provider prices out of source into a versioned `data/llm_prices.json` (or fetch into `provider_keys.meta`), date-stamp them, and surface "estimated vs confirmed" on the cost report; add a startup warning when a routed model resolves to `cost_usd=None`.
- **Effort**: M

## 5. Retry policy ignores `Retry-After` and uses unexplained constants — a rate-limited call burns its ~2 s budget then falls to template
- **Lens**: 🌀 Ambiguity
- **Severity**: Medium
- **Category**: magic numbers / rate-limit edge case
- **File**: pipeline/jobfit/llm/base.py:263
- **Observation**: Backoff is `time.sleep(0.5 * (2**attempt) + random.uniform(0, 0.25))` with `_MAX_ATTEMPTS = 3` (base.py:34). The constants 0.5, the `2**attempt` base, the 0.25 jitter, and "3" have no recorded rationale beyond "the policy proven in gemini.py," there is no max-backoff cap, and crucially the loop never reads the `Retry-After` header that providers return on 429s — it classifies the error as transient (is_transient_error, base.py:113-130) and then waits its own blind ~0.5 s/~1 s. With only two sleeps before raising, total tolerance before giving up is well under ~2 s, so any 429 asking for a multi-second wait deterministically exhausts retries and drops the call to its deterministic fallback (and `map()`'s `max_workers=4`, base.py:319, fires four such requests at once, amplifying the limit).
- **Why it matters**: Rate-limit handling is the one failure mode a multi-provider layer is supposed to ride out; instead a brief 429 burst silently converts LLM-quality output to template output, and the undocumented constants make the behavior hard to reason about or tune per provider.
- **Recommendation**: Parse and honor `Retry-After` (cap to the call timeout) before falling back to capped exponential backoff; name the constants (or move to config) with a one-line rationale; consider per-provider concurrency limits for `map()`.
- **Effort**: S
