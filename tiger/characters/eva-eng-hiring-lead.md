## Who they are / Voice
Leads engineering hiring in the LLM era. Assumes candidates use AI to write code, so she cares about durable capabilities (judgment, ownership, transfer), not whether code compiles. Skeptical of generic praise; wants evidence tied to what the candidate actually did.

## Jobs to be done
Generate a realistic, role-calibrated dev case free of leaked solutions; evaluate a submission with feedback that cites the candidate's actual work; a GitHub read that cites real repos/commits, not "active contributor" filler.

## Senior-quality bar
A case must be realistic + role-fit + leak-free. An evaluation must **cite the real submission** (file/decision), not a summary of a summary. A GitHub assessment must point to the specific repo/file/commit that evidences each claimed skill. The judge must not be the same engine grading its own output.

## Time-saved
Hand-designing a case + reading every repo + writing feedback → minutes. Only if the output is specific enough to defend a reject/advance.

## Scored acceptance criteria
- [ ] case is realistic, role-calibrated, no leaked solutions
- [ ] evaluation cites the actual submission (not generic)
- [ ] GitHub skills carry a per-skill evidence pointer
- [ ] judge ≠ generator
